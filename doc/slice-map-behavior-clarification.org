* Issue Identification

The current slice handling behavior in go-cfg has **duplication issues** where default values are processed multiple times, leading to confusing results.

** Current Problematic Behavior

*** Slices - BROKEN (Duplication)
From README.org output:
#+begin_example
# With defaults: Tags:[web api production]  
# User specifies: --tags=staging,debug
# ACTUAL Result: Tags:[web api production web api production staging debug]
# EXPECTED Result: Tags:[staging debug]
#+end_example

From microservice example:
#+begin_example  
# Default: discovery.endpoints: "consul:8500,etcd:2379"
# ACTUAL Result: ["consul:8500", "etcd:2379", "consul:8500", "etcd:2379"]
# EXPECTED Result: ["consul:8500", "etcd:2379"]
#+end_example

*** Maps - WORKING CORRECTLY
From microservice testing:
#+begin_example
# Default: features: "auth:true,metrics:true,tracing:false,caching:true"
# User specifies: --features=debug:true,custom:false
# ACTUAL Result: {"custom": false, "debug": true} ✅
# EXPECTED Result: {"custom": false, "debug": true} ✅
#+end_example

** Root Cause Analysis

The issue is specifically with **slice processing**:
1. Default slice values are being set multiple times during processing
2. This creates duplication: `[default, default, user_values]`
3. Maps appear to work correctly with replacement behavior
4. The problem is in the slice value initialization/processing pipeline

* Proposed Fix

** 1. Root Cause - Slice Default Duplication

The issue is that slice defaults are being processed multiple times in the configuration pipeline, not that Set() is appending. The StringSliceValue.Set() method already replaces correctly:

#+begin_src go
func (ssv *StringSliceValue) Set(s string) error {
    // This already replaces, not appends
    ssv.value = strings.Split(s, ",")  // ✅ Replacement behavior
    return nil
}
#+end_src

** 2. Fix Default Processing Pipeline

The real issue is in how defaults are processed multiple times. We need to prevent duplicate default processing:

#+begin_src go
// In registerField, ensure defaults are only set once
func (fc *FlagConfig) registerField(...) error {
    // ...existing code...
    
    case fieldType.Kind() == reflect.Slice:
        elemType := fieldType.Elem()
        switch elemType.Kind() {
        case reflect.String:
            var defaultSlice []string
            if defaultValue != "" {
                // Only process defaults once
                defaultSlice = strings.Split(defaultValue, ",")
            }
            
            // Create slice value with defaults
            stringSliceValue := NewStringSliceValue(defaultSlice)
            fc.FlagSet.Var(stringSliceValue, flagName, usage)
            
            // Store updater to copy final values back
            fc.storeSliceUpdater(flagName, field, stringSliceValue)
}
#+end_src

** 3. Prevent Double Processing in Configuration Load

Ensure configuration loading doesn't duplicate slice processing:

#+begin_src go
// In layered integration, prevent duplicate processing
func LayeredConfigure(config interface{}) error {
    // Stage 1: Load file configuration (sets initial values)
    if err := loadConfigFiles(config); err != nil {
        log.Printf("File loading failed (continuing): %v", err)
    }

    // Stage 2: Flag processing - should replace file values, not append
    if err := cfg.FlatNest(config); err != nil {
        return fmt.Errorf("flag processing failed: %w", err)
    }
    
    return nil
}
#+end_src

* User Communication

** Breaking Change Notice
This fix represents a **breaking change** for users who might be relying on the current (buggy) append behavior. However, the current behavior is:

1. **Unintuitive** - Users expect replacement, not appending
2. **Buggy** - Default values are being duplicated  
3. **Inconsistent** - Other types (string, int, bool) replace defaults correctly

** Migration Guide
For users who need additive behavior, provide explicit guidance:

#+begin_src go
// OLD (broken): --tags=staging,debug results in [web,api,production,staging,debug]
// NEW (correct): --tags=staging,debug results in [staging,debug]

// If you need additive behavior, handle it explicitly:

    DefaultTags []string `default:"web,api,production"`
    ExtraTags   []string `json:"extra_tags"`
}

// Combine in your application logic:
allTags := append(config.DefaultTags, config.ExtraTags...)
#+end_src
