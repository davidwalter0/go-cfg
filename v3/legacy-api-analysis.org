* Overview

This document analyzes the API surface of the legacy go-cfg library located at ~/org/go-configurator/apps/rotation/go-cfg/ to understand the backward compatibility interface that needs to be maintained when migrating to use the v3 module internally.

* Package Declaration

The legacy package is declared as:
#+begin_src go
package cfg // import "github.com/davidwalter0/go-cfg"
#+end_src

* Key Dependencies

The legacy system depends on:
- =github.com/davidwalter0/go-flag= - Custom flag parsing library
- =gopkg.in/yaml.v3= - YAML parsing
- =github.com/mattn/color= - Terminal colorization

* Configuration Loading Patterns

** Struct Tag Support
The legacy system supports these struct tags:

- =json= - Field name and omit options
- =default= - Default value
- =doc=, =help=, =usage= - Documentation
- =short= - Short flag name
- =required= - Mark field as required
- =ignore= - Skip field processing

** Environment Variable Patterns

Environment variables are generated using these patterns:
- CamelCase fields become UPPER_SNAKE_CASE
- Prefixes are applied based on struct names
- =CFG_KEY_PREFIX= environment variable overrides prefixes
- =CFG_DECORATE= controls decoration behavior

** Flag Patterns

Flags are generated using these patterns:
- CamelCase fields become lower-kebab-case
- Prefixes are applied consistently with environment variables
- Custom flag library =github.com/davidwalter0/go-flag= is used

* Key Behaviors

** Test Mode Behavior
When =SetTestMode()= is called:
- No flags are registered (=registerFlags = false=)
- No flag parsing occurs (=SetAutoParse(false)=)
- Environment variables and defaults are still processed
- Field values are set directly via reflection

** Configuration Processing Flow
1. Validate struct pointers with =CheckArgs()=
2. Enter each struct with =Enter()=
3. Parse struct recursively with =ParseStruct()=
4. Process each field with =Field.SetField()=
5. Register flags if not in test mode
6. Apply environment variables and defaults

** Prefix Handling
- Struct names become prefixes by default
- =CFG_KEY_PREFIX= environment variable overrides
- =CFG_DECORATE=false= disables all prefixing
- Different functions provide different prefix behaviors

* Missing FlatNest Function

**NOTE**: The =FlatNest= function mentioned in the request was not found in the legacy codebase. The closest functions are:
- =Nest()= - For hierarchical nesting
- =Simple()= / =Unwrap()= / =Bare()= - For flat processing without prefixes

* Backward Compatibility Requirements

To maintain backward compatibility, the v3 module must provide:

1. **All exported functions** with identical signatures
2. **Same struct tag support** (json, default, doc, required, ignore, etc.)
3. **Same environment variable naming** (UPPER_SNAKE_CASE with prefixes)
4. **Same flag naming** (lower-kebab-case with prefixes)
5. **Test mode behavior** (no flag registration/parsing)
6. **Global store behavior** 
7. **Same error types and messages**
8. **Prefix and decoration control**
9. **Custom help text support**
10. **Configuration persistence via Stor type**

* Implementation Strategy

The v3 module should:
1. Provide a compatibility layer that wraps the new pflag-based implementation
2. Maintain the same global state variables
3. Implement the same configuration processing flow
4. Support all the legacy struct tags and behaviors
5. Provide the same test mode functionality
6. Maintain the same error handling and validation
